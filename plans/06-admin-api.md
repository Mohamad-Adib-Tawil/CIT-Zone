# 06 — لوحة الويب الإدارية وعقود الخدمات

## واجهة الإدارة

تظهر للإدارة فقط بعد تحقق الخادم من الدور. تكون صفحاتها في تطبيق ويب منفصل متجاوب مع الجوال: ملخص مؤشرات، المنهج، المواد والدورات، الدروس والوسائط، المرفقات، الطلاب والاستحقاقات، طلبات نقل الأجهزة، وسجل الإجراءات. اجعل كل صفحة قابلة للاستخدام على الهاتف واللوحي، مع بحث وتصفية وترقيم للبيانات الكبيرة. لا تُحمّل كل الطلاب أو الوسائط دفعة واحدة.

النطاق يشمل أيضاً التقويم والباقات والإيصالات والقسائم إن اعتُمدت، MCQ/Gemini، الإعلانات والإشعارات والدعم، تقارير الوقت، واستيراد صور العلامات ومراجعتها واعتمادها. تقنية الويب لم تُحدد؛ دور أدمن واحد ولا Teacher Role.

تفاصيل الهوية البصرية، خريطة الشاشات، الرحلات، ومعايير قبول الواجهة في [خطة تصميم لوحة الإدارة](admin-dashboard/README.md).

### عمليات إدارة المحتوى

| العملية | التحقق المطلوب قبل النجاح |
| --- | --- |
| إنشاء موضع مادة | قسم وسنة وفصل موجودة، وعدم تكرار الربط |
| إنشاء دورة | مادة وأستاذ وصفي موجودان، وعدم وجود دورة منشورة فعالة أخرى حسب سياسة MVP |
| إضافة درس | موضع ترتيب فريد، عنوان صالح، وربط فيديو غير عام |
| رفع فيديو | ملف ضمن الحجم والنوع المسموح، تذكرة رفع قصيرة العمر، ثم حدث معالجة موثوق |
| نشر دورة | درس أول جاهز ومجاني، جميع الدروس المنشورة وسائطها جاهزة، وعدم وجود أخطاء تراخيص |
| أرشفة دورة | سياسة واضحة لما يحدث لاستحقاقات الطلاب والتنزيلات الموجودة |
| منح استحقاق | طالب ودورة صالحان، مصدر المنح ومدة الصلاحية واضحان، سجل تدقيق |
| نقل جهاز | تحقق من الطالب والسبب وسياسة التهدئة، إبطال الجلسات القديمة، سجل تدقيق |

## واجهات API مفاهيمية

هذه عقود أولية لتحديد المسؤوليات وليست مسارات نهائية. عرّف OpenAPI أو عقداً مكافئاً قبل بدء العميل والخادم بالتوازي.

| المسار المقترح | الغرض | أهم شرط |
| --- | --- | --- |
| `POST /auth/google/exchange` | التحقق من Google وإنشاء/استعادة مستخدم | رمز هوية صحيح موجه للتطبيق |
| `POST /devices/register` | ربط مفتاح التثبيت | معاملة جهاز واحد وإثبات سلامة |
| `POST /devices/transfer` | طلب/تنفيذ نقل الجهاز | سياسة تحقق وسجل تدقيق |
| `GET /curriculum` | الأقسام والسنوات والفصول والمواضع المنشورة | إرجاع القائمة المسموحة فقط |
| `GET /courses/{id}` | تفاصيل دورة منشورة والدروس المتاحة | لا يكشف أسرار الوسائط |
| `POST /lessons/{id}/playback` | تفويض التشغيل | نشر + استحقاق/معاينة + جهاز |
| `POST /lessons/{id}/offline-license` | بدء/تجديد ترخيص تنزيل | استحقاق + جهاز + سياسة تنزيل |
| `GET /attachments/{id}/access` | تفويض فتح المرفق | الهوية والقسم؛ PDF مجاني دون اشتراك فيديو؛ سياسة بقية المرفقات منفصلة |
| `GET /me` | ملف الطالب وجهازه واستحقاقاته | هوية صحيحة |
| `/admin/curriculum`, `/admin/courses`, `/admin/lessons` | CRUD محكوم بالنشر | دور إدارة وتحقق قيود المجال |
| `/admin/students`, `/admin/entitlements`, `/admin/devices` | إدارة وصول الطلاب والنقل اليدوي | دور إدارة وسجل تدقيق |
| `/admin/payments`, `/admin/term-instances` | مراجعة إيصالات وباقات وتقويم | معاملة ومنع تكرار وتفويض |
| `/admin/grade-imports` | صور خاصة ثم استخراج ومطابقة ومراجعة واعتماد | لا نشر OCR تلقائي ولا صورة جماعية للطالب |
| `/admin/exercises`, `/admin/announcements`, `/admin/support` | تمارين وإعلانات ودعم | تحقق نطاق وإخفاء مفاتيح الإجابات والأسرار |

## قواعد العقد

- استخدم معرفات ثابتة لا أسماء عربية كمفاتيح، وتواريخ UTC في النقل مع عرضها محلياً.
- لكل عملية كتابة تحقق مدخلات على الخادم ورد أخطاء منتظم ورمز ثابت؛ لا يمر `providerAssetId` أو رابط التخزين إلى الطالب إلا عند ضرورة تقنية مدروسة.
- عمليات الرفع تصدر تذكرة قصيرة العمر من الخادم؛ يراقب الخادم حدث الاكتمال من المزود ويتحقق من مصدره. لا يعتبر إشعار العميل بنجاح الرفع دليلاً على جاهزية الفيديو.
- حدّد pagination وsort وحدود الحجم لكل قائمة؛ عالج التعارض بإصدار سجل/`updatedAt` لمنع كتابة الإدارة فوق تعديل أحدث.
- طبق مبدأ أقل الصلاحيات على رموز خدمة التخزين والفيديو، مع تدوير مفاتيح وسجل استخدام.
- لا تخلط منح الاستحقاق اليدوي بعملية دفع غير محسومة. خزّن `source` ومرجع العملية حتى يمكن إضافة الدفع لاحقاً دون فقدان الأثر.

## حالات واجهة الإدارة

كل صفحة تعرض التحميل والفراغ والخطأ، وتمنع الإرسال المكرر. رفع الفيديو يعرض `uploading/processing/ready/failed`، مع إعادة محاولة آمنة. إجراء النشر يحتاج معاينة قائمة تحقق فعلية من الخادم، وتأكيداً للمسؤول لأن أثره يظهر للطلاب. سجل التدقيق للقراءة فقط من التطبيق.
