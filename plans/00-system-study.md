# دراسة نظام CIT Zone

## 1. فكرة النظام

تطبيق تعليمي لطلاب معهد الحاسوب، يعرض المواد حسب **القسم والسنة والفصل**، ويتيح مشاهدة الدروس والمرفقات وفق صلاحية الطالب. تدير الإدارة المنهج والدورات والطلاب من لوحة داخل تطبيق Flutter. يتصل تطبيق الطالب ولوحة الإدارة بخادم API خاص؛ الخادم هو المرجع للأدوار والصلاحيات والاشتراكات والمحتوى.

> حالة المشروع الآن: توجد واجهات معاينة للطالب والإدارة وهوية Google مهيأة من جهة التطبيق. بيانات الواجهات تجريبية، ولا يوجد خادم API أو منهج رسمي متصل بعد.

## 2. المستخدمون والأدوار

| الدور | ما يستطيع فعله |
| --- | --- |
| زائر | قد يتصفح المنهج والدرس التعريفي إذا اعتمدت سياسة الزائر. هذه السياسة ما زالت قراراً مفتوحاً. |
| طالب | يسجل عبر Google، يستعرض المواد، يتابع دوراته، يشاهد الدروس المجانية أو المصرح بها، ويدير ملفه وتنزيلاته. يربط حسابه بجهاز نشط واحد وفق سياسة الخادم. |
| إدارة | تدير الطلاب والمنهج والدورات والدروس والمرفقات والنشر والاستحقاقات وطلبات نقل الجهاز، بصلاحيات يتحقق منها الخادم. |

لا يوجد حساب أستاذ مستقل في النسخة الأولى؛ اسم الأستاذ وصف للدورة، والإدارة مسؤولة عن المحتوى.

## 3. المزايا الأساسية

- كتالوج مواد مصنف إلى قسم البرمجيات والشبكات، ثم السنة والفصل.
- فصل المادة عن موضعها الدراسي وعن الدورة؛ يمكن للمادة الظهور في أكثر من موضع مع بقاء محتواها مشتركاً.
- صفحة دورة فيها وصف وأستاذ ودروس ومرفقات. أول درس منشور مجاني للتعريف بالدورة، وبقية المحتوى يتطلب استحقاقاً.
- تشغيل فيديو ومرفقات محمية، مع خطة مستقبلية للتنزيل داخل التطبيق بعد إثبات دعم DRM والرخص دون اتصال.
- ملف شخصي يعرض معلومات الحساب والحقوق والتنزيلات وحالة الجهاز، ويقدم مساراً للدعم أو طلب نقل الجهاز.
- لوحة إدارة داخل التطبيق لإدارة الطلاب والمنهج والدورات والدروس والمرفقات والنشر والاستحقاقات.
- توسعات لاحقة: المقالات والنصائح وأسئلة الدورات، بعد استقرار النسخة الأولى.

## 4. حالات الاستخدام الرئيسية

| المعرّف | المستخدم | حالة الاستخدام والنتيجة |
| --- | --- | --- |
| UC-01 | طالب | يسجل عبر Google؛ يتحقق الخادم من الهوية ويصدر جلسة CIT Zone. هوية Google وحدها لا تمنح دوراً أو اشتراكاً. |
| UC-02 | طالب | يحاول الدخول من جهاز ثانٍ؛ يرفض الخادم الربط المتزامن ويعرض تعارض الجهاز وخطوات الدعم أو النقل المعتمدة. |
| UC-03 | طالب | يختار القسم والسنة والفصل ويبحث عن مادة؛ يرى المواد والدورات المنشورة فقط. |
| UC-04 | زائر/طالب | يفتح صفحة الدورة ويشاهد الدرس الأول المجاني إذا سمحت سياسة النشر بذلك. |
| UC-05 | طالب | يفتح درساً أو مرفقاً مدفوعاً؛ يتحقق الخادم من الجلسة والاستحقاق قبل إصدار إذن التشغيل أو الملف. |
| UC-06 | طالب | يشاهد دوراته وتنزيلاته وبياناته؛ يطلب المساعدة أو نقل الجهاز وفق سياسة الحساب. |
| UC-07 | إدارة | تنشئ أو تعدل موضع مادة أو دورة أو درساً ومرفقاً، ثم تراجع المحتوى وتنشره. كل تغيير مهم يسجل في سجل تدقيق. |
| UC-08 | إدارة | تبحث عن طالب وتراجع حقوقه وحالة جهازه أو طلب النقل، ضمن الصلاحيات الإدارية الممنوحة. |
| UC-09 | إدارة | تمنح أو تلغي استحقاقاً بعد اعتماد سياسة الدفع أو المنح؛ تحفظ العملية ذرياً وتوثق منفذها وسببها. |

## 5. رحلة الاستخدام المختصرة

```text
فتح التطبيق ← تسجيل Google ← تحقق الخادم والجهاز
           ← اختيار القسم/السنة/الفصل ← فتح مادة ودورة
           ← درس تعريفي مجاني ← استحقاق معتمد
           ← مشاهدة الدروس والمرفقات المصرح بها
```

أما الإدارة فتدخل إلى لوحة الإدارة بعد أن يثبت الخادم دورها، ثم تدير المنهج والمحتوى والطلاب والاستحقاقات. لا يظهر مسار الإدارة للطالب كوسيلة تفويض؛ الخادم يرفض طلباته الإدارية حتى لو عُدّل التطبيق.

## 6. قواعد العمل والحماية

- تسجيل Google يثبت هوية الحساب فقط. الخادم يتحقق من رمز Google ويصدر جلسة التطبيق والدور.
- يفرض الخادم جهازاً نشطاً واحداً للطالب داخل معاملة، ويوفر مساراً واضحاً لحالات التعارض والنقل.
- صلاحية الدورة منفصلة عن تسجيل الدخول. لا يصدر رابط تشغيل أو مرفق خاص دون استحقاق صالح.
- لا تصبح الدورة متاحة قبل النشر، ولا يتغير الدرس المجاني الأول بسبب ترتيب غير متحقق منه.
- لا تخزن أسرار الخادم أو روابط الوسائط طويلة العمر أو مفاتيح DRM داخل التطبيق أو المستودع.
- لا يُنزّل فيديو MP4 مكشوفاً ولا يُستخدم مفتاح تشفير ثابت داخل التطبيق. حماية المحتوى تقلل التسريب ولا تضمن منعه كلياً.
- تستخدم الواجهة حالات واضحة للتحميل والفراغ والخطأ وانقطاع الشبكة وانتهاء الجلسة، مع إعادة محاولة مناسبة.

## 7. المتطلبات غير الوظيفية

- Flutter وDart مع null safety، تنظيم feature-first وفصل العرض والمنطق والبيانات، وCubit لإدارة حالات الواجهة.
- الالتزام بمبادئ SOLID عند توضيح المسؤوليات والحدود، واختبار حالات النجاح والرفض والفشل.
- واجهة عربية RTL متجاوبة مع الهاتف واللوحي، قابلة لتكبير الخط، وتدعم قارئ الشاشة وأهداف لمس مناسبة.
- API موثق بأخطاء ثابتة وترقيم للقوائم، مع تحقق صلاحيات على الخادم وسجل تدقيق للعمليات الحساسة.
- حماية جلسات المستخدم والبيانات الشخصية، وعدم وضع الأسرار في Git أو سجلات التطبيق.

## 8. خارج النسخة الأولى

حسابات مستقلة للأساتذة، بث مباشر، امتحانات وشهادات، محادثة وتعليقات، مقالات المجتمع وأسئلة الدورات، ولوحة ويب. لا تنفذ المدفوعات أو التنزيل دون اتصال قبل حسم السياسات واختبار التقنية.

## 9. قرارات مطلوبة قبل الإطلاق

1. اعتماد المنهج الرسمي وأسماء المواد ومواضعها وإصداراتها الدراسية.
2. تحديد سياسة الزائر، والأسعار أو المنح أو آلية الدفع ومدة الاستحقاق.
3. تحديد لغة الخادم واستضافته وقاعدة البيانات وآلية إدارة الجلسات.
4. اختيار مزود الفيديو وإثبات تجربة DRM على Android وiOS وسياسة الرخص دون اتصال.
5. اعتماد سياسة نقل الجهاز، وهوية التطبيق البصرية، وإعدادات متاجر التطبيقات.
