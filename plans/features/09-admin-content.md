# 09 — إدارة المنهج والدورات والدروس والوسائط

**الهدف:** الإدارة تنشئ المنهج والمادة والدورة ذات الأستاذ الوصفي، ترفع وسائط ومرفقات، تراجع الجاهزية ثم تنشر. اللوحة داخل Flutter وفق [تفصيل التصميم](../admin-dashboard/README.md). الشاشات الحالية معاينة debug لا تحفظ شيئاً.

## قرارات قبل التكامل

D01/D02 للمنهج، D08 لمزود الفيديو، D11 توزيع واجهة الإدارة، D12 خصوصية المرفقات، D14 حقوق الأستاذ والمحتوى، D15 الصلاحيات. يجب وجود هوية إدارة مثبتة من الخادم. لا ترفع مادة أو فيديو حقيقياً قبل حقوق النشر وعقد الوسائط.

## مهام عمودية بالترتيب

1. **إدارة المادة والموضع:** نموذج يختار `Subject` قائماً أو ينشئ جديداً، ثم `CurriculumPlacement` لقسم/سنة/فصل/ترتيب؛ يعرض المواضع الأخرى. API كتابة يتحقق من فريدية الموضع ونسخة المنهج ويعيد 409 مفهوماً.
2. **المسودة:** إنشاء `Course` لمادة وأستاذ وصفي واحد، حفظ مرحلي مع `version`/ETag، تحقق حقول خادم؛ لا تسمح بدورة منشورة فعالة ثانية. محرر يوضح التغييرات غير المحفوظة ويمنع ضياعها عند الرجوع.
3. **الدروس:** إضافة وتعديل وترتيب `Lesson` داخل المسودة بمعاملة وقيد ترتيب فريد. عند تغيير الأول، يظهر أثر المجانية قبل التأكيد؛ الخادم يعيد فحص سياسة الدرس الأول.
4. **الرفع:** الخادم يصدر تذكرة رفع قصيرة العمر لأصل محدد النوع/الحجم؛ التطبيق يعرض `uploading` منفصلة عن `processing`، ثم `ready/failed` عبر polling محدود أو حدث موثوق. أضف إعادة محاولة آمنة لا تنشئ درساً مكرراً.
5. **المرفقات:** تحقق نوع وحجم ومحتوى ملف، مخزن خاص، ربط بالدرس وسياسة ظهور مستقلة. عرض واضح للمرفق العام إن اختير بعد D12؛ لا تستنتج عمومية مرفق الدرس المجاني.
6. **الجاهزية والنشر:** endpoint `validate` يرجع أخطاء بحسب الحقل والدرس/الوسيط؛ شاشة مراجعة تعرض ما سيراه الطالب. `publish` يتطلب نسخة مسودة ومفتاح منع تكرار وتأكيداً صريحاً، وينفذ معاملة وسجل تدقيق. إعادة جلب الدورة بعد النتيجة.
7. **الأرشفة/الاستبدال:** لا حذف صلب لدورة لها استحقاقات أو رخص؛ اطلب قرار D05 وتأثيره، ثم endpoint مؤكد ومسجل.

## ملكية الملفات والطبقات

- Flutter: `features/admin` الموجود يُقسم تدريجياً إلى Cubit قائمة/تفاصيل/محرر/رفع/نشر بحسب دورة الحياة. لا تضع كل الكتابات في `AdminDashboardCubit`. استخدم repositories وDTOs منفصلة وUseCases لقواعد النشر؛ حافظ على الواجهة responsive من الخطة.
- الخادم: مسارات `/admin/curriculum`, `/admin/subjects`, `/admin/courses`, `/admin/lessons`, `/admin/media`, `/admin/attachments` بعد تثبيت OpenAPI. كل مسار يفحص دور الإدارة ويكتب audit عند التغيير.
- قاعدة البيانات: قيود المواضع والدورة المنشورة وترتيب الدروس، معاملات النشر، ونسخ التعديل. عامل webhook يعزل توقيع المزود وفشل المعالجة.

## حالات واجهة لازمة

تحميل/فراغ/خطأ لكل قائمة؛ بحث وترقيم من الخادم؛ `409` تعارض نسخة مع عرض الأحدث؛ `403` فقد دور؛ ملف غير مسموح؛ وسائط قيد المعالجة؛ فشل فحص الجاهزية؛ نشر جارٍ؛ نشر نجح لكن تحديث الشاشة تأخر؛ انتهاء جلسة ومسودة محلية غير محفوظة. لا تعرض زر «نشر» نشطاً عندما يمنع الخادم النشر.

## قبول واختبارات

- API/DB: تغيير موضع مشترك لا ينسخ الدورة؛ طلب نشران متوازيان لا ينشئان نسختين؛ درس أول غير جاهز أو غير مجاني يرفض؛ webhook غير موثوق يرفض؛ طالب يستدعي admin يرفض؛ audit يسجل كل تغيير.
- Flutter: رحلة مسودة→درس→رفع→جاهزية→نشر على staging، تعارض تعديل، مغادرة مع تغييرات، بحث وعودة، 320/600/1024dp وRTL، قارئ شاشة.
- **يقبل** عندما يرى الطالب الدورة بعد نجاح النشر الحقيقي فقط، ويمكن للإدارة تكرار فتحها فتجد الحالة نفسها على الخادم، ولا تخرق أي عملية سياسات الوسائط أو الاستحقاقات.
