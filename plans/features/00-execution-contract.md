# 00 — عقد تنفيذ إلزامي لكل مهمة

## تعريف البداية

لا تبدأ كتابة ميزة قبل أن تكون بطاقة المهمة أدناه مكتملة. إذا تعذر حسم قرار مانع، أنجز فقط نموذج واجهة أو تجربة تقنية مع تسمية واضحة ومنع دخوله نسخة الإنتاج.

```text
معرف المهمة / القسم / رابط الخطة:
الهدف من منظور الطالب أو الإدارة:
داخل النطاق / خارج النطاق:
قرار المنتج المعتمد ورابط السجل وتاريخه:
الأدوار المسموحة وحالات الرفض:
كيانات المجال والقيود والتزامن:
عقد API: الطلب، الاستجابة، رموز الخطأ، الترقيم، الإصدار:
الحالات البصرية: تحميل، فراغ، نجاح، خطأ، دون شبكة، انتهاء جلسة:
ملفات Flutter والخادم والمنصات والهجرة والتوثيق المتأثرة:
اختبارات المجال، العقد، Cubit، Widget، التكامل والأجهزة:
مقياس الأداء أو المراقبة الذي قد يتأثر:
معيار القبول القابل للاختبار:
```

إن لم يوجد خادم بعد، أنشئ عقداً متفقاً عليه واختبار fake للواجهة، ولا تسمِّ ذلك اتصالاً فعلياً. لا تختلق endpoint أو سياسة دفع أو مدة رخصة وتقدمه كقرار معتمد.

## التسلسل الملزم

1. **افحص الموجود:** اقرأ البنية والاختبارات والقرار؛ ابحث عن نموذج أو خدمة مشتركة قائمة قبل إضافة أخرى. حدد أثر التغيير في التوجيه، DI، Android/iOS، الترحيلات، الخصوصية والوثائق.
2. **ثبت العقد:** عرّف كيانات المجال، invariants، حدود الثقة، طلب/استجابة JSON بأسماء ثابتة عندما يُحسم API، ورموز خطأ مستقرة. أبقِ DTO في `data` ولا تربط `domain` بـFlutter أو HTTP.
3. **اختبر الخادم أولاً في القواعد الحساسة:** التفويض، التكرار، التزامن، النشر، الاستحقاق، الجهاز والوسائط. أضف قيد قاعدة بيانات أو معاملة حيث يلزم، لا فحص واجهة فقط.
4. **نفذ الشريحة Flutter:** data source يحول الأخطاء، repository يحقق العقد، use case يطبق قرار المجال عند الحاجة، Cubit يدير الحالة، الصفحة تركب Widgets صغيرة. لا ترسل الشبكة من `build`.
5. **غطِّ الحالات:** تحقّق من التحميل والفراغ والخطأ وانتهاء الجلسة والتعارض وإعادة المحاولة والإلغاء. لا تعرض `0` إن فشل تحميل مؤشر؛ لا تكرر طلب كتابة عند إعادة المحاولة بلا مفتاح منع تكرار.
6. **اكمل المنصات:** عند Google أو DRM أو تخزين آمن أو ملفات أو إشعارات، راجع `AndroidManifest.xml`، Gradle، `Info.plist`، entitlements، جسر المنصة، إعدادات التوقيع، وأذونات النظام. لا تضف أذناً لا تحتاجه.
7. **تحقق وسلّم:** شغّل `fvm flutter pub get --enforce-lockfile` ثم التنسيق والتحليل والاختبارات المناسبة، واختبارات الخادم والبناء والأجهزة عند تأثرها. اذكر نتائجها وما لم يُنفذ.

## حدود الطبقات وملكية الحالة

```text
Page/Widget -> Cubit -> UseCase عند وجود قاعدة عمل -> Repository interface
                                              Data implementation -> API/secure local store
API route -> auth/authorization -> application service -> transaction -> repository/database
```

- حالات الشاشة `loading/ready(empty|content)/failure` مع تحديث يحتفظ بالبيانات السابقة حين يكون ذلك آمناً. حالة كل عملية كتابة مستقلة عن حالة القراءة، وزرها يُعطّل أثناء الطلب.
- محول أخطاء واحد يربط `code` القادم من الخادم برسالة عربية آمنة؛ لا تعرض نص استثناء أو stack trace للمستخدم.
- مصادر الحقيقة: الخادم للاستحقاق والدور والمنهج والنشر وربط الجهاز؛ مخزن الجهاز للملفات والرخص المحلية المؤقتة؛ Cubit لحالة العرض المؤقتة فقط.
- عند نجاح كتابة، أعد جلب الكيان أو حدّث الحالة من استجابة الخادم الموثوقة؛ لا تفترض نجاحاً لمجرد إغلاق الحوار.
- للقراءات الكبيرة: ترقيم من الخادم، مرشحات ممثلة في الطلب، حفظ حالة البحث عند الرجوع، وإلغاء النتائج القديمة عند تغيّر البحث بسرعة.
- افصل الحقول المحمية عن logging والتحليلات. لا تخزن أو تسجل رمز Google أو refresh token أو مفتاح DRM أو رابط تشغيل أو مرفق خاص.

## بوابات مراجعة الكود

| البوابة | يرفض الدمج إذا... |
| --- | --- |
| المنتج | حُوّل افتراض أو بيانات demo إلى سياسة منشورة، أو لم يُحسم قرار مانع |
| الأمن | القرار الأمني في العميل فقط، أو endpoint بلا تحقق دور/استحقاق، أو سر في المستودع |
| المجال | مادة/موضع/دورة مختلطة، أو تغير ترتيب الدرس الأول دون فحص، أو كتابة بلا معاملة حيث يلزم |
| العمارة | منطق عمل في Widget، أو DTO يتسرب إلى domain، أو Cubit شامل غير قابل للاختبار |
| التجربة | حالة خطأ أو فراغ أو عودة أو تكبير نص غير معالجة، أو زر يوهم بتنفيذ غير موجود |
| التشغيل | لا سجل تدقيق لعملية حساسة، أو فشل غير مرصود، أو لا توجد خطة ترحيل لتغيير البيانات |
| التحقق | اختبار النجاح وحده، أو لم تُختبر صلاحيات الرفض والتعارض، أو الفحوص تفشل |

## شكل تقرير التسليم

اذكر: الملفات المعدلة، السلوك المنجز، العقود/الترحيلات، الاختبارات بنتائجها، حالات المنصات التي جُربت، والقرارات/المخاطر المتبقية. لا تستخدم كلمة «مكتمل» إذا بقيت وصلة أساسية بالخادم أو إعداد منصة أو اختبار جهاز حقيقي تتطلبه الميزة.
