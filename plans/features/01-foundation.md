## تحديث النطاق 2026-10-08

هذا الاعتماد هو المرجع عند قراءة التفاصيل أدناه؛ تفاصيل التشغيل المعلقة في سجل القرارات لا تُستنتج من أمثلة العقود السابقة.

تطبيق الطالب Flutter ولوحة ويب مستقلة وفق D11؛ تقنية الويب تحتاج اعتماداً. Google إلزامي وفق D03 ودور أدمن واحد وفق D15. مخططات guest/admin داخل تطبيق الطالب في المسودات السابقة لا تمثل routes إنتاج جديدة: الاستقبال ثم Google ثم جلسة ثم إكمال الملف ثم الطالب/تعارض، والإدارة في الويب. تحافظ المعاينة القديمة على debug فقط حتى شريحة إزالة مستقلة.

أضف بوابات CI للويب بعد اعتماد تقنيته. قدرات الهوية وDRM والتخزين قابلة لإعادة الاستعمال خلف عقود واختبارات، دون فرض framework مشترك أو multi-tenancy. لا تكون كيانات المعهد داخل حزمة وسائط عامة.

**الهدف:** إطار Flutter يستضيف واجهة الطالب مع إبقاء معاينة الإدارة الحالية مرجع تطوير، يتصل بخادم خاص بأمان، ويختبر دون بيانات حقيقية. **الحالة:** معاينة الإدارة الحالية توفر Theme وCubit وشاشات؛ لا تمثل أساس تسجيل دخول أو API إنتاجي.

## شرائح التنفيذ

1. ثبت إصدار Flutter/FVM ونسخ الحزم في lockfile؛ نظف وصف القالب فقط عند لمس الملف. عرّف بيئات `dev/staging/prod` عبر قيم بناء غير سرية، مع عنوان API مختلف، ومنع تشغيل demo في الإنتاج.
2. أنشئ `app/router` يملك مسارات splash/signIn/completeProfile/student/deviceConflict؛ توجيه الإدارة في تطبيق الويب المستقل؛ لا تستنتج الدور من متغير محلي. ارجع بعد استعادة الجلسة إلى الوجهة المطلوبة إذا سمح الدور.
3. أضف عميل HTTPS بمهل محددة، إلغاء، request ID، parsing محدود الحجم، وتصنيف أخطاء: شبكة، وقت، 401، 403، 409، 429، 5xx، وبيانات غير صالحة. لا تسجل رؤوس Authorization أو body حساس.
4. عرّف `Result` أو استثناءات مجال موحدة؛ `data` فقط تترجم JSON/HTTP، و`presentation` تترجم رمز المجال إلى نص واجهة. ضع آلية تجديد جلسة واحدة متزامنة، بلا حلقات 401.
5. عرّف composition root أو DI واضحاً؛ أنشئ repository الحقيقي من config، وfake للاختبارات، وdemo مسموحاً في debug فقط. لا تضع singleton قابل للتغيير بلا مالك دورة حياة.
6. ابنِ نظام تصميم طالب وإدارة متسقاً: ألوان وخطوط/مسافات ورموز وحالات أزرار ورسائل، RTL، وضع فاتح/داكن، دعم عرض صغير وتكبير النص. لا تثبّت الشعار النهائي قبل D16.
7. أضف screen states مشتركة عند تكرار فعلي، مراقبة أعطال بلا بيانات شخصية، feature flags من مصدر موثوق عند الحاجة، وCI للخادم عندما ينشأ.

## خريطة ملفات مقترحة

`lib/app/{router,composition_root,environment}.dart`؛ `lib/core/{network,error,security,theme,widgets}/...`؛ `test/app/...` و`test/core/...`. الملفات الفعلية تتبع بنية المشروع الموجودة. لا تنقل كود الإدارة التجريبي إلا في مهمة مستقلة مع اختبارات رجوع.

## عقود مطلوبة

- لكل استجابة: `requestId`، ورمز خطأ ثابت عند الفشل، وتواريخ UTC؛ إصدارات API معلنة وخطة توافق مع الإصدارات القديمة.
- `GET /health` للتشغيل فقط بلا معلومات أسرار؛ `GET /me` لاحقاً لاستعادة دور موثوق. ثبّت الأسماء النهائية في OpenAPI قبل التنفيذ المتوازي.
- لا تتعامل مع `HTTP 200` ذي JSON ناقص كنجاح؛ اختبر parsing وحدود الحقول.

## اختبارات وقبول

- Unit: mapping لكل فئة خطأ، منع تسجيل الرموز، تجديد متزامن واحد، timeout/cancel. Widget: splash/خطأ/فراغ/RTL/320dp وتكبير نص. Integration: بيئة staging تستجيب وتمنع عنوان prod في اختبار dev.
- **يقبل** عندما تفتح نسخة debug ببيانات اختبار واضحة، وتفتح نسخة release فقط تدفقاً مصرحاً، ويتغير التوجيه بعد استعادة الجلسة من الخادم، ولا توجد أسرار في البناء أو السجلات، وتنجح الفحوص على Android/iOS المستهدفين.
