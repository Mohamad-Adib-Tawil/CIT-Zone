# تنفيذ Clean Architecture / SOLID / Either — 2026-10-26

المسؤول Mohamad Adib Tawil مع Codex. التكليف «نفذ الخطة» بعد فحص البنية الحالية؛ نطاق Flutter الطالب والأساس الموجود. المرجع متابعة D29 وبطاقة عقد التنفيذ بتاريخ26 أكتوبر. لا Backend أو SQL أو Dashboard إنتاجي أو نشر أو تعديل مرئي.

## التسلسل المنفذ

1. قراءة الخطط والتسليم المحلي وحفظ نسخة وبصمات لملفات العمل قبل التعديل خارج المستودع؛ خط أساس543 اختباراً. محاولة Notion الحية404، ولا ادعاء تسليم أحدث.
2. إضافة fpdart1.2.0 فقط واستبدال Result/Success/Failure بـEither/Right/Left في الهوية والإعدادات والتخزين والوسائط، وترحيل المستهلكين والاختبارات وحذف النتيجة القديمة. عكس ترتيب المعاملين إلى Failure ثم Value صريح.
3. ترحيل عقد StudentRepository التجريبي إلى Either بفشل مجال محدد، وحالات تحميل/نتيجة فارغة/فشل/refresh؛ حفظ القائمة عند الفشل ونشر نسخة قائمة غير قابلة للتعديل. لا تحويل عينات المنهج إلى بيانات إنتاج أو API مفترض.
4. فصل `AppConfigRemoteDataSource` ليملك طلب GET app/config والرؤوس والdecoder؛ المستودع يملك تنسيق معلومات المنصة وملكية الإلغاء وتحويل الأخطاء. فحص الإلغاء قبل/بعد النقل، وحماية فتح رابط المتجر واحتواء استثناء المنصة.
5. استكمال تصنيف400/404/422 في ApiFailure مع بقاء المهل/حدود الحجم/السلامة/الإلغاء ورفض redirects/retries التلقائية. اختبار العقد المشترك نفسه لكل من Dio وIo دون تخفيف الحماية.
6. منع عمليات جديدة بعد close في Cubits المتأثرة، وإبقاء النتيجة المتأخرة غير منشورة. constructor injection قائم؛ لا use case أو BaseCubit فارغ.
7. استخراج سياسة مسارات المعاينة والتحقق من إطار الطالب من سجله وإطار الإدارة من سجله؛ معالجة cross-frame IDs التي كان الحارس يسمح بها خطأ. dispose للتوجيه قابل للتكرار، وحراسة production مستمرة.
8. تشديد AST: core/errors وcore/media مستقلان كالمجال، منع اعتماد ميزة على data لميزة أخرى، منع presentation من app، وحصر go_router في app/router وGetIt في app/di. السماح المحدد بـfpdart في domain.
9. توثيق أدوار المعماري ومنفذ Flutter ومراجع API/الأمن ومراجع الجودة/الأداء، وربطها بـAGENTS وCLAUDE والقاعدة الهندسية الدائمة؛ لا تشغيل وكلاء أو تعديل مسار الفريق.

## ما يبقى مرتبطاً بتسليم مستقل

- جلسة الخادم: عقد exchange ونوع الرمز والتجديد والإبطال وربط الجهاز وتزامنها؛ لا يصبح GoogleIdentity session.
- كتالوج الإنتاج: DTOs ومخططات النجاح/الفشل والترقيم والمرشحات والتفويض. معاينة StudentRepository الحالية تبقى debug ولا توصف كتكامل.
- مسارات الطالب الإنتاجية وحفظ الوجهة بعد انتهاء الجلسة: بعد وجود session state الموثوق وواجهاتها المعتمدة. مسارات Figma ليست هذه الرحلات.
- DRM/التنزيل والإشعارات والمنصات والتوقيع: وفق قراراتها وخطة النشر؛ لا تتفعل بسبب تغيير عقد النتائج.
- معاينات الإدارة القديمة وتفاصيل StudentPreview تحتفظ بالتنقل الداخلي القائم؛ ترحيلها إلى تطبيق إدارة/كتالوج إنتاجي مستقل ليس ضمن هذه الشريحة.

## الأثر والأمان

لا تغيير في نماذج البيانات/SQL أو الأدوار أو Figma أو native setup أو الحد الأدنى للنظام؛ لذلك أثر البيانات غير منطبق ولا إذن/حزمة منصة جديدة. Either قيمة Dart صغيرة دون I/O أو عمل startup جديد. لا نتائج حجم/زمن بدء/ذاكرة قبل القياس على الجهاز المرجعي. لا تعديلات على ملفات المصدر الخام في docs/notion أو عمل مسار Claude.

معيار قبول الشريحة: نجاح التبعيات المقفلة والتنسيق/التحليل والحدود/التوليد والاختبارات المناسبة، واختفاء Result القديم من lib/test/integration_test، وبقاء مسارات التطوير محجوبة عن production. [الأدلة ونتائج التنفيذ](../../reports/engineering-foundation/architecture-2026-10-26/README.md) تسجل ما تحقق فعلاً وما لم يتحقق.
