# بطاقة تنفيذ — استعادة هوية Google وعرضها في معاينة الملف

- **القسم:** الهوية والملف الشخصي؛ `features/02-identity-devices.md` و`features/08-profile-support.md`.
- **هدف المستخدم:** بعد إعداد OAuth، يختار الطالب حساب Google، يرى بيانات هويته، ويمكن استعادتها عند فتح التطبيق مجدداً والخروج منها. يستطيع مراجعة شكل ملفه في معاينة التطوير.
- **داخل النطاق:** استعادة Google الخفيفة، عرض الاسم والبريد في معاينة الملف عند توفرهما، توثيق معرّفات التطبيق وبصمة توقيع debug. **خارج النطاق:** جلسة CIT Zone، دور، ربط جهاز، محتوى مدفوع، تخزين رمز، أو نشر المعاينة في الإنتاج.
- **القرار:** D07 خادم API خاص؛ مشروع Google Cloud ومعرفات OAuth لم يحددها صاحب المنتج بعد. لا يمكن تنفيذ التبادل أو التفويض دون الخادم. تبقى المعاينة في debug فقط.
- **الصلاحيات والرفض:** هوية Google ليست صلاحية طالب أو إدارة. إلغاء الاختيار أو فشل الاستعادة يعيد شاشة الترحيب. فشل الخروج يعرض خطأ ويبقي الهوية مرئية.
- **الكيانات والقيود:** `GoogleIdentity` للاسم والبريد والصورة فقط؛ ID token يبقى في SDK مؤقتاً ولا يُسجل أو يُخزن. لا يوجد تزامن خادم بعد.
- **العقد:** `GoogleIdentityGateway` يعيد هوية أو `null` في الاستعادة. `POST /auth/google/exchange` مؤجل إلى حين تثبيت عقد API وتنفيذ الخادم.
- **الحالات:** غير مهيأ، استعادة جارية، لا حساب سابق، هوية معروفة، فشل الاستعادة الصامت، اختيار جارٍ، إلغاء، فشل، خروج جارٍ/فاشل.
- **الملفات:** `lib/features/auth`، `lib/app`، `lib/features/student/presentation`، اختبارات Cubit وWidget، وثائق التنفيذ. لا تغييرات جديدة مطلوبة في Android/iOS إلى حين إدخال OAuth IDs؛ إعدادات URL scheme السابقة موجودة.
- **الاختبارات:** استعادة ناجحة/لا حساب/فشل، ظهور هوية Google الحقيقية في معاينة الملف، خروج؛ تنسيق وتحليل واختبارات Flutter، وبناء المنصات المتاحة. الاختبار الحقيقي على جهاز مرتبط بـOAuth لاحقاً.
- **الأداء والمراقبة:** طلب استعادة واحد عند بدء التطبيق؛ لا تكرار داخل `build` ولا طباعة رموز.
- **القبول:** عند نجاح الاستعادة تظهر هوية Google وحدها، وتبقى معاينة الملف موسومة بأنها تجريبية؛ عند غياب OAuth أو فشل الاستعادة يمكن للمستخدم اختيار الحساب يدوياً، ولا يصل إلى ميزات محمية.
