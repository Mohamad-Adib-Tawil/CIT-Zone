# 12 — الأساس الهندسي لحاسوبجي

اعتماد هندسة التنفيذ: 2026-10-16 بطلب صاحب المنتج. يكمّل الخطط 02/04/05/08 ولا يغير سياسات المنتج أو القرارات المفتوحة. شرط الهواتف الضعيفة والقديمة معتمد؛ ميزانياته الرقمية الأولية في الخطة 14 أهداف تحقق وليست نتائج قياس.

## الحالة الفعلية

**متابعة FND-03/04/05:** Dio مسجل كسولاً خلف ApiClient بعد توافق Io/Dio، مع سياسة URL/JSON/error وملكية مهلة/إلغاء/close مشتركة. adapters التخزين جاهزة ومختبرة محلياً: secure session secret مستقل وكاش Drift schema1 لمعرفات صفحات الحساب فقط، دون تسجيلهما في bootstrap أو استعمالهما لجلسة Google. عقود الوسائط ومالك تشغيل واحد موجودة في domain بلا SDK أو URLs أو مفاتيح. [الأدلة والحدود الحالية](../reports/engineering-foundation/transport-storage-2026-10-16/README.md)؛ ما يلي من حالة تاريخية يقرأ معها، ولا يصبح تنزيل/DRM أو API إنتاجياً.

Flutter 3.47.2 مثبت بـFVM؛ Cubit وGoogle وأساس `ApiClient` ومعاينات الطالب والإدارة موجودة. الحزم المضافة مسجلة في الخطة 13؛ الخادم وDRM والتنزيل والاشتراك لم تصبح ميزات إنتاجية بتثبيتها. معاينات `DemoStudentRepository` و`DemoAdminRepository` تبقى داخل التطوير، ونسخة بيانات Notion الأصلية لا تعدل.

## شكل النظام

- طالب Flutter لـAndroid/iOS، مع بيانات قابلة للكاش واستهلاك محدود للشبكة والذاكرة.
- إدارة ويب مستقلة متجاوبة؛ لا تُشحن أدوات OCR وإدارة الطلاب داخل تطبيق الطالب الإنتاجي.
- API خاص واحد مقسم إلى وحدات: الهوية/الجهاز، المنهج، المحتوى، الاستحقاق/الدفع، الوسائط، التمارين، العلامات، الدعم، الإشعارات والتدقيق.
- PostgreSQL هو مخطط البيانات المحلي الحالي. اعتماده على الاستضافة وتقنية الخادم يثبت في D07؛ لا تختَر إطار خادم أو مزوداً تلقائياً.
- عمال خلفية للترميز وwebhooks وOCR وتجميع التقارير وطلبات Gemini والإشعارات. معاملات وoutbox/idempotency للآثار المتكررة؛ لا توزيع مبكر إلى microservices.
- التخزين الخاص وCDN يحملان الوسائط؛ API يمنح التفويض ولا يمرر كل بايت فيديو عبر خادم التطبيق.

## حدود الاعتماد

**تفعيل FND-02 — 2026-10-16:** شريحة هوية Google تستخدم `GoogleIdentityRepository` في domain وتطبيقه في data فوق gateway القائم، و`Result<T, F>` واحد في `core/errors` بنوعي Success/Failure، دون حزمة Either إضافية. Cubit يستهلك النتائج ويربط رمز الفشل برسالة presentation آمنة. أخطاء `ApiFailure` تبقى عقد نقل؛ تحولها data عند وجود مستهلك API فعلي، ولا تغير هذه الشريحة IoApiClient. لا use case تمرير بلا قاعدة عمل. get_it scoped في composition root وgo_router في app/router مفعّلان؛ [تقرير التنفيذ](../reports/engineering-foundation/architecture-2026-10-16/README.md) يحدد المسارات والحدود والأدلة. حقن StudentPreviewCubit بدل إنشاء demo repository في الصفحة. المعاينات القديمة ليست ميزات إنتاجية.

العرض يعتمد على عقد repository أو use case يحمل قاعدة عمل؛ تطبيق repository في data يستخدم API/cache/gateway. `domain` Dart مستقل بلا Flutter أو Dio أو SQLite أو أنواع مزود DRM. DTO لا ينتقل إلى العرض كعقد مجال. لا تستدعِ `get_it` من الكيانات؛ resolution في composition root ثم constructor injection، وCubit قصير العمر يملكه route.

- Cubit الافتراضي، وBloc عندما تحتاج الأحداث ترتيباً/إلغاءً لا يحققه التدفق البسيط بوضوح؛ لا مدير حالة شامل للتطبيق.
- أخطاء الشبكة القائمة في `core/network` تحول إلى إخفاقات آمنة للمجال؛ لا تصنع نظام Result ثانياً إن كان العقد الحالي كافياً.
- استخدم Freezed للنماذج المركبة عند فائدته؛ Dart sealed classes للنماذج الصغيرة، ولا حاجة لحزمة مساواة إضافية آلياً.
- يبقى `ApiClient` عقد النقل، وأضيف close لملكية الموارد. `DioApiClient` مفعل بعد اختبارات توافق الإلغاء والمهلة الكلية وحد الاستجابة مع Io؛ تنفيذ Io واختباراته باقية، والميزات لا تعرف Dio.
- يملك `go_router` المسارات بعد شريحة ترحيل مختبرة؛ redirect يمنع العرض الخاطئ والخادم يفرض التفويض.
- موارد الفيديو/PDF والجلسة والتنزيل لها owners صريحة و`dispose/close/cancel`، مع معالجة الخلفية والخروج وتبديل الحساب.

## حدود المجال والبيانات

المادة تختلف عن موضعها في قسم/سنة/فصل وعن الكورس المستقل. مصدر إكمال الدرس التمارين المعتمدة، لا مدة الفيديو. العلامات الرسمية من OCR مراجع/اعتماد إداري لا من إدخال الطالب. التقدم الأكاديمي لا يضم كورسات أو مواد خارج خطته؛ D18/D22/D26/D27 لا تحسمها مكتبة أو افتراض في الكود.

Drift لفهرس محلي وبيانات محدودة/قابلة للاستعادة، وليس نسخة كاملة من قاعدة الخادم. لا تخزن رموز جلسة أو مفاتيح DRM في SQLite. قسّم الكاش حسب الحساب ونسخة المحتوى؛ حذف جلسة/تبديل حساب يعزل البيانات. حفظ نقطة مشاهدة محلياً ليس إكمال درس أو منح استحقاق. لا ترسل تمارين/مدفوعات/طلب دعم كنجاح أوفلاين؛ سياسات هذه العمليات ما زالت تتطلب اتصالاً.

## مزايا مخططة محسنة ضمن النطاق

1. بحث مرقّم يحتفظ بالمرشحات عند الرجوع، يلغي الطلب القديم، ويعرض الكاش مؤشراً بتاريخ تحديثه.
2. مشغل يتذكر نقطة الاستئناف، جودة متكيفة وخيار اقتصادي، ومعالجة واضحة لعدم دعم DRM دون تعطيل التصفح وPDF المسموح.
3. مركز تنزيلات: الحجم والمساحة والجودة والحالة، توقف/استئناف قابل للإصلاح، حذف فردي/كلي؛ لا تنزيل كبير تلقائي.
4. PDF أكاديمي مجاني بإصدارات واضحة؛ PDF كورس VIEW_ONLY أو ENCRYPTED_IN_APP وفق سياسته. تجربة حمايته مستقلة عن الفيديو.
5. اشتراك وتقويم من الخادم، مراجعة إيصالات وتدقيق، وإشعارات قليلة لا تكشف تفاصيل علامة/ملف محمي على شاشة القفل.
6. OCR وعامل Gemini في الخادم بحدود تكلفة ووقت ومراجعة بشرية للعلامات؛ لا نموذج AI أو OCR ثقيل في الهاتف الضعيف.
7. دعم غير لحظي، حالة طلب واضحة، مرفقات مصغرة وحدود حجم، وسهولة وصول عربية RTL ونص مكبر.

أي تغيير بصري أو حالة جديدة يحتاج إطار/قرار حسب الخطة 11، وأي سياسة جديدة تحتاج سجل قرار. الترميزات والجودة وحدود الرخص والتزامن توصيات تقنية حتى تجارب D08/D09/D28.

## ترتيب التنفيذ والتحقق

ابدأ بتجربة DRM والأجهزة الأقل قدرة، ثم أساس الجلسة/الجهاز وAPI، ثم كتالوج/PDF وشريحة دروس، ثم الاستحقاقات والتشغيل والتنزيل، ثم التمارين والعلامات والتقارير وفق الخارطة الحالية. تُرحّل كل ميزة بشريحة رأسية، وتختبر رفض الوصول كما يختبر النجاح.

قبل ربط كل حزمة: اختبر العقد، ثم Android/iOS، وقِس الحجم والذاكرة. `pub get` لا يكفي لإثبات Native ABI/DRM/Keychain أو توافق هاتف قديم. لا ترفع minSdk/deployment target أو تغير Flutter/AGP لمجرد إسكات تبعية.
