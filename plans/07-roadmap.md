# 07 — خطة التنفيذ المرحلية

الترتيب أدناه يحدد التبعيات. لا يعني وجود مرحلة أن قراراتها حُسمت. لكل مرحلة نتيجة قابلة للمراجعة؛ لا تقفز إلى واجهة جميلة قبل صحة الوصول والمحتوى.

لكل مرحلة، اتبع [خطط بناء الأقسام](features/README.md) و[عقد تنفيذ المهمة](features/00-execution-contract.md) قبل الكود. الملف المرحلي يحدد الترتيب، وملف القسم يحدد السلوك والعقود والحالات والاختبارات.

## المرحلة 0: حسم المتطلبات وتجربة المخاطر

**العمل:** استلام المنهج الرسمي، تحديد Android/iOS المستهدفين وسياسة الزائر والاشتراك/الدفع ونقل الجهاز ومدة رخصة عدم الاتصال؛ اختيار مزود خادم ومزود فيديو مرشح؛ بناء تجربة DRM المذكورة في `05-media-offline.md`.

اعتمد أيضاً خريطة شاشات الإدارة وهوية التصميم الأولية ونماذج رحلات النشر والمنح ونقل الجهاز وفق [خطة لوحة الإدارة](admin-dashboard/README.md)، قبل تحويلها إلى Widgets.

**النتيجة:** سجل قرارات محدث، مخطط بيانات معتمد، عقد مبدئي للـAPI، وتقرير تجربة Android/iOS يثبت أو يرفض قابلية التنزيل المحمي.

**شرط الإكمال:** لا توجد قرارات مانعة لإطلاق MVP، ومزود الفيديو يدعم المتطلبات المثبتة أو تُعدل المتطلبات بقرار صريح.

## المرحلة 1: أساس المشروع والخادم

**العمل:** تنظيف قالب Flutter، إعداد التوجيه والثيم وDI وعميل API والأخطاء والبيئات؛ إنشاء الخادم ومخطط البيانات والترحيلات وسجل التدقيق والإعدادات الآمنة وCI الأساسي.

**النتيجة:** تطبيق يفتح على شاشات أساسية مرتبطة ببيئة تطوير، وAPI به health ونسخ عقود واضحة وترحيلات قابلة للإعادة.

**شرط الإكمال:** تحليل Dart ينجح، اختبارات الأساس تنجح، وأسرار الإنتاج غير موجودة في المستودع.

## المرحلة 2: Google والطالب والجهاز والأدوار

**العمل:** تسجيل Google، تبادل الهوية مع الخادم، تسجيل المفتاح وإثبات سلامة التطبيق، حالة تعارض الجهاز، استعادة الحساب، وإدارة الدور الإداري.

**النتيجة:** طالب يدخل من جهاز واحد وإدارة تدخل بصلاحية خادم، مع رسائل واضحة للتعارض والخروج.

**شرط الإكمال:** اختبارات ربط متزامن، رفض جهاز ثانٍ، سحب الجلسة، منع مستخدم عادي من API الإدارة.

## المرحلة 3: المنهج والكتالوج ولوحة الإدارة الأساسية

**العمل:** إنشاء أقسام/سنوات/فصول/مواد/مواضع؛ إدخال المنهج الرسمي؛ بطاقات المواد والدورات وتصفية وبحث؛ صفحات إدارة المنهج والدورة والأستاذ الوصفي.

**النتيجة:** تظهر المادة في أكثر من موضع دون نسخ دورة أو استحقاق.

**شرط الإكمال:** قيود البيانات واختبارات التكرار والترتيب والنشر، وتجربة تصفح على هاتف ولوحي.

## المرحلة 4: الدروس والبث والمرفقات

**العمل:** رفع ومعالجة ونشر الفيديو، تشغيل الدرس التعريفي، تفويض الدروس الخاصة، مرفقات خاصة، واجهة الدرس، واستئناف التشغيل.

**النتيجة:** دورة منشورة واحدة لكل مادة في MVP؛ الزائر/الطالب يرى ما تسمح به السياسة، والمحتوى المدفوع محمي من الخادم.

**شرط الإكمال:** اختبارات السماح والرفض لجميع مسارات الوسائط والمرفقات، وتحقق من عدم تسرب رابط عام أو سر للمستخدم.

## المرحلة 5: الاستحقاق ثم التنزيل المحمي

**العمل:** إدارة الاستحقاقات يدوياً أو عبر طريقة الاشتراك المعتمدة، ثم تنفيذ التنزيل الأصلي والرخص وتجديدها ومسحها ومراقبة المساحة.

**النتيجة:** طالب مستحق يشغل الفيديو داخل التطبيق دون إنترنت وفق مدة رخصته، وغير المستحق يُرفض.

**شرط الإكمال:** نجاح مصفوفة `05-media-offline.md` على جهازين حقيقيين على الأقل لكل نظام مدعوم، مع تقرير حدود الحماية. لا تُطلق هذه المرحلة إن لم تنجح تجربة DRM.

## المرحلة 6: تثبيت الجودة والإطلاق

**العمل:** مراقبة الأعطال والقياسات، إمكانية الوصول، اختبار شبكات ضعيفة، مراجعة أمنية، سياسة خصوصية، اختبار متجر، نسخ احتياطي واستعادة للخادم، وخطة استجابة للدعم.

**النتيجة:** إصدار تجريبي مغلق ثم إطلاق تدريجي مع قدرة على إيقاف ميزة أو سحب وصول مخترق.

**شرط الإكمال:** تحقق قائمة `08-quality.md`، مراقبة أخطاء الإنتاج، وإجراء استرجاع مختبر.

## بعد النسخة الأولى

1. منشورات ومقالات ونصائح؛ حدد مؤلف المحتوى الفعلي، آلية مراجعة الإدارة، الوسائط، والتبليغ قبل البناء.
2. أسئلة الدورات؛ حدد من يجيب، الإشراف، إشعارات المتابعة، والظهور العام/الخاص.
3. دور أستاذ مستقل فقط إذا تغيرت سياسة الإدارة؛ يتطلب صلاحيات ونشر ومراجعة وتدقيقاً جديداً.
4. إصدارات أو دورات متعددة للمادة، وتقارير تعلم وتحليلات عند وجود حاجة مثبتة.
