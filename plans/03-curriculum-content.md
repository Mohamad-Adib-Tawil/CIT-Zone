# 03 — المناهج والمحتوى ونموذج البيانات

## اعتماد 2026-10-08 وتحديث نطاق 2026-10-14

28 مادة فريدة إجمالاً بالقسمين، نحو 10 مشتركة تقديرياً، سنتان وفصلان لكل سنة. قاعدة 7 مواد للفصل ومواضع المادة ومشروع التخرج تُراجع بالمنهج قبل البيانات. القسم والسنة والفصل توصيات عرض فقط؛ الكتالوج يعرض كل المواد المنشورة ويتيح الاشتراك بأي مادة دون تغيير المسار. `StudentAcademicProfile` للقسم/السنة/الفصل ومواد إعادة معتمدة إدارياً، و`AcademicTermInstance` لتواريخ فصل فعلي؛ طلب إعادة لا يثبت رسوباً ولا يمنح حقاً.

PDF كامل للمادة وPDF لكل جلسة، مجانيان بعد الدخول لكل الطلاب، يُعدّهما طلاب حاليون وتراجع الإدارة النشر والحقوق. يضاف `SubjectDocument`/ربط مادة إلى جانب مرفق الجلسة، مع version ونطاق ظهور؛ لا تجبر PDF كامل المادة على `lessonId`. المرفقات الأخرى تخضع لسياسة منفصلة. بيانات الاشتراك والباقات والنتائج في الخطط 06 و13 وليست علامات تجريبية.

متطلبات Hasobjy المعتمدة تضيف كتالوج كورسات تقنية مستقل عن المنهج الأكاديمي، لكل كورس اشتراك ومواد ومحتوى وتمارين. أول فيديو للكورس مجاني، ومدة صلاحية اشتراكه ينفذها الخادم؛ لا يستنتجها من الفصل الأكاديمي. صفحة Notion تترك مدة الكورس مفتوحة، فتكون قيمة المدة ضمن بيانات الكورس ولا تثبت كرقم افتراضي.


## الفصل بين المصطلحات

| الكيان | معناه | حقول أساسية مقترحة |
| --- | --- | --- |
| `Department` | قسم البرمجيات أو الشبكات | `id`, `name`, `status` |
| `AcademicYear` | سنة أولى أو ثانية | `id`, `level`, `label` |
| `Term` | فصل أول أو ثانٍ | `id`, `sequence`, `label` |
| `Subject` | مادة أكاديمية واحدة مستقلة عن موقعها | `id`, `code`, `title`, `description` |
| `CurriculumPlacement` | ظهور مادة في قسم/سنة/فصل | `id`, `subjectId`, `departmentId`, `yearId`, `termId`, `sortOrder`, `active` |
| `Course` | دورة تعليمية للمادة، لها إصدار وحالة نشر | `id`, `subjectId`, `instructorId`, `version`, `status`, `publishedAt` |
| `TechnicalCourse` | كورس مستقل خارج القسم والسنة والفصل، له تصنيف وحالة نشر | `id`, `categoryId`, `title`, `description`, `status`, `accessDuration` |
| `InstructorProfile` | اسم وصورة ووصف أستاذ للعرض؛ ليس حساب دخول | `id`, `displayName`, `bio`, `avatarAssetId` |
| `Lesson` | درس مرتب داخل الدورة | `id`, `courseId`, `position`, `title`, `summary`, `status`, `videoAssetId` |
| `Attachment` | مرفق درس خاص أو عام | `id`, `lessonId`, `storageKey`, `type`, `visibility`, `size`, `status` |
| `Entitlement` | حق طالب في دورة | `id`, `userId`, `courseId`, `startsAt`, `expiresAt`, `status`, `source` |
| `TechnicalCourseEntitlement` | حق الطالب في كورس تقني مستقل بمدة يقررها الخادم | `id`, `userId`, `technicalCourseId`, `startsAt`, `expiresAt`, `status`, `source` |
| `MediaAsset` | مرجع ملف فيديو عند المزود وحالة المعالجة | `id`, `provider`, `providerAssetId`, `status`, `duration`, `drmProfile` |

هذه أسماء مفاهيمية وليست ترحيلات نهائية. لا تحفظ بيانات بطاقات دفع أو أسرار وسائط في هذه الجداول.

## علاقات وقيود أساسية

- `Subject` ← عدة `CurriculumPlacement`، مع قيد فريد على `(subjectId, departmentId, yearId, termId)` لمنع تكرار الموضع نفسه.
- عدد دورات/مدرسي المادة غير محسوم حسب تعديل Notion؛ لا يفرض قيد دورة نشطة واحدة. SQL المصدر يربط دروس المادة مباشرة بحاوية SUBJECT، بينما Course الأكاديمي في الخطة مفهوم منفصل؛ D26 يحسم الإصدارات والعلاقة قبل بناء API المحتوى. تحفظ الأرشفة والتاريخ دون نسخ المواد المشتركة.
- بيانات المدرس للعرض فقط بلا حساب Teacher. عدد المدرسين وعلاقتهم بالدورة ينتظر D26؛ لا يجوز نشر قائمة بلا دروس معاينة جاهزة.
- `TechnicalCourse` لا يتطلب `CurriculumPlacement` أو `Subject`، ويملك قائمة دروس وتمارين وPDF وسياسة اشتراك مستقلة. يمكن مشاركة بنية تشغيل الدرس بعد فصل نوع الحاوية في المجال.
- `Lesson.position` فريد داخل الحاوية. أول N دروس منشورة هي المعاينة (افتراض 1)، ويحسبها الخادم من free_preview_count وترتيب المنشور، دون علم حر لكل درس. فحص أثر إعادة الترتيب وتغيير N جزء من عملية النشر.
- لا تُحذف الدورات المنشورة التي عليها استحقاقات حذفاً نهائياً. استخدم الأرشفة وإصدارات المحتوى وسجّل التغيير.
- إن كان المنهج يتبدل بين دفعات الطلاب، أضف `CurriculumVersion`/عاماً دراسياً إلى الموضع قبل الإدخال الفعلي؛ هذا قرار منتج مفتوح.

## أمثلة تبين عدم التكرار

- مادة «قواعد البيانات» قد تظهر في قسم البرمجيات/السنة الأولى/الفصل الثاني وقسم الشبكات/السنة الثانية/الفصل الأول. كلا الموضعين يشيران إلى `Subject` واحد؛ بطاقة الدورة لا تتكرر في قاعدة المحتوى.
- إذا احتاج قسم الشبكات شرحاً مختلفاً للمادة، تقرر الإدارة هل هي مادة مستقلة برمز مختلف أم إصدار دورة مختلف. لا تنسخ `Lesson` بلا قرار لأن ذلك يشتت الاستحقاقات والتحديثات.

## حالات المحتوى

`draft → uploading → processing → ready → published → archived`، وحالة `failed` للرفع/المعالجة. اجعل الانتقالات صريحة في الخادم. لا يتلقى الطالب إلا `published`، ولا يُصدر الخادم رابط تشغيل قبل تحقق حالة الفيديو ونظام الترخيص. يحتفظ الدرس بأثر تغيير الوسائط بعد النشر حتى لا يتسبب استبدال فيديو في كسر تنزيلات قائمة دون سياسة.

## إدخال قائمة المواد

ملف المنهج الرسمي مطلوب من صاحب المنتج: أسماء المواد، رموزها إن وجدت، القسم، السنة، الفصل، وترتيب الظهور. جهّز قالب استيراد ومراجعة قبل إدخال البيانات. لا تُنشئ قائمة مواد كاملة من الذاكرة؛ أمثلة الطلب ليست بيانات اعتماد.

## أسماء SQL المعتمدة للتصميم المحلي

الأسماء المفاهيمية أعلاه ليست أسماء جداول إلزامية. `academic_years` في SQL تعني العام التقويمي مثل 2026/2027، بينما `study_year` مستوى الطالب 1..2. `department_subjects` تمثل مواضع المادة بمفتاح القسم/المادة/السنة/الفصل. `learning_containers` أب SUBJECT/COURSE؛ الأخير كورس تقني مستقل. لا توجد علاقة دورات أكاديمية متعددة أو ملفات أستاذ معتمدة في SQL المصدر؛ D26 يحسمها قبل التنفيذ.

`database/schema.sql` يحتوي الوحدات التسع كاملة، مع `grading_schemes` و`grade_revisions` و`product_bundle_subjects` و`protected_pdf_licenses`. [القاموس](../database/data-dictionary.md) و[ERD](../database/erd/README.md) يتولدان من المخطط نفسه. PDF الأكاديمي DOWNLOADABLE ومجاني، وPDF الكورس VIEW_ONLY أو ENCRYPTED_IN_APP وغير مجاني؛ روابط PDF تحافظ على مالك واحد قبل النشر.
