# 01 — نظام التصميم للوحة الإدارة

## شخصية الواجهة

**واضحة، موثوقة، هادئة.** التركيز على إنهاء مهمة إدارية دون ضياع: تباين قوي، ترتيب بصري ثابت، ونصوص حالة دقيقة. تجنب التدرجات الثقيلة والظلال البارزة والحركة المتكررة. استخدم لون الحالة إلى جانب نص وأيقونة؛ اللون وحده لا يشرح معنى النشر أو الخطأ.

## رموز بصرية أولية

هذه قيم بدء للتصميم المرئي، ويُختبر مظهرها على أجهزة فعلية قبل اعتماد الهوية النهائية:

| الرمز | فاتح | الاستخدام |
| --- | --- | --- |
| `primary` | `#2546D2` | الإجراء الأساسي، العنصر المختار، الروابط المهمة |
| `onPrimary` | `#FFFFFF` | النص على الزر الأساسي |
| `background` | `#F6F8FC` | خلفية الصفحة |
| `surface` | `#FFFFFF` | البطاقات والحوارات |
| `textPrimary` | `#0B1220` | العناوين والبيانات الأساسية |
| `textSecondary` | `#475467` | الشرح والبيانات المساندة |
| `success` | `#027A48` | منشور، جاهز، عملية نجحت |
| `warning` | `#B54708` | انتظار أو معالجة تحتاج متابعة |
| `error` | `#B42318` | فشل أو إيقاف أو إجراء مرفوض |
| `accent` | `#0E9384` | إبراز زخرفي محدود؛ لا يستخدم لنص صغير على الأبيض |

الألوان النصية المقترحة الأساسية والحالات الداكنة تحقق مبدئياً تبايناً لا يقل عن `4.5:1` على الأبيض؛ أعد فحصها بعد توليد `ColorScheme` الفعلي، وفي الوضع الداكن، وعلى جميع أسطح البطاقات. لا تنسخ هذه الأكواد مباشرة إلى كل widget؛ ضعها في `ThemeData` ورموز تصميم مركزية. [مرجع Flutter للتباين وحجم اللمس](https://docs.flutter.dev/ui/accessibility/ui-design-and-styling).

| الرمز | داكن مقترح | الاستخدام |
| --- | --- | --- |
| `primary` | `#A8BAFF` | عناصر التحكم البارزة؛ النص عليها `#0B1220` |
| `background` | `#0B1220` | خلفية الصفحة |
| `surface` | `#111B2E` | البطاقات والحوارات |
| `textPrimary` | `#F8FAFC` | النص الأساسي |
| `textSecondary` | `#CDD5E0` | النص المساند |
| `success` | `#53D1A0` | حالة النجاح |
| `warning` | `#FFBE73` | حالة الانتظار |
| `error` | `#FF9B8F` | حالة الفشل |

هذه الألوان الداكنة قيم بدء؛ اختبر التباين عند التطبيق مع حالات التحديد والتعطيل والحقول، لا مع الخلفية وحدها.

## الخطوط والتدرج الطباعي

- العربية هي الأساس وRTL افتراضي. استخدم خطاً عربياً واضحاً وثابت الوزن، مع تجربة قراءة الأرقام والرموز الإنجليزية والشفرة قبل اعتماد ملف خط خارجي؛ يبقى خط النظام بديلاً عند تعذر التحميل.
- عنوان الصفحة: 24–28 نقطة، وزن واضح. عنوان القسم: 18–20. عنوان البطاقة: 15–16. النص الأساسي: 14–16. النص المساعد: 12–14 دون أن يصبح مصدر معلومات لا يمكن قراءته.
- الأرقام المهمة أكبر بصرياً من عناوينها، لكن لا تُعرض بلا تسمية ووحدة/فترة زمنية. عرض التاريخ والوقت يتبع الإعداد المحلي مع حفظ UTC في البيانات.
- استخدم `TextTheme` واحداً، واسمح بتكبير خط النظام؛ لا تثبت ارتفاع بطاقة يمنع تمدد النص.

## المسافات والأشكال والحركة

| العنصر | قاعدة بدء |
| --- | --- |
| مقياس المسافات | 4، 8، 12، 16، 24، 32 نقطة منطقية |
| حواف البطاقات | نصف قطر 12–16؛ لا تكرر مستويات متداخلة بلا داعٍ |
| حواف الحقول | 10–12 مع خط حدود واضح عند التركيز والخطأ |
| مساحة لمس | 48×48 نقطة منطقية على الأقل للعناصر التفاعلية |
| الظلال | خفيفة ومحدودة؛ استخدم تغير السطح/الحدود لترتيب المستويات |
| الحركة | انتقالات قصيرة هادئة للحالة والتنقل؛ احترم إعداد تقليل الحركة |

لا تجعل اختفاء رسالة النجاح المؤقتة الوسيلة الوحيدة لتأكيد النشر أو المنح؛ تظهر الحالة النهائية في سجل العنصر نفسه.

## الاستجابة والتنقل

- التصميم يعتمد **عرض المساحة المتاح** عبر `LayoutBuilder`/قيود التخطيط، لا نوع الجهاز. هذه قاعدة موصى بها في [Flutter](https://docs.flutter.dev/ui/adaptive-responsive/general).
- **أقل من 600dp:** شريط تنقل سفلي بأربع وجهات: الرئيسية، المحتوى، الطلاب، المزيد. يضم «المزيد» الطلبات والسجل والإعدادات؛ يظهر تنبيه الطلبات أيضاً في الرئيسية. صفحة التفاصيل تفتح فوق وجهتها مع زر رجوع واضح.
- **600–1023dp:** `NavigationRail` مختصر للوجهات الرئيسية؛ قوائم المحتوى/الطلاب تستخدم عرض قائمة ثم تفاصيل حسب المساحة. لا تتحول الجداول العريضة إلى تمرير أفقي غير منضبط.
- **1024dp فأكثر:** تنقل جانبي موسع وقائمة + تفاصيل حيث يفيد ذلك؛ حد أقصى مناسب لعرض النماذج والنصوص حتى لا تتمدد عبر الشاشة كاملة. هذه العتبة قرار تصميم مبدئي، تُراجع في نماذج فعلية.
- لا تعرض أكثر من مستويين بصريين دائمين من التنقل. حافظ على عنوان الصفحة وموضع المستخدم والزر الأساسي ثابتة بين المقاسات.

## مكونات قابلة لإعادة الاستخدام

| المكون | قواعده |
| --- | --- |
| `AdminShell` | شريط علوي وتنقل متكيف ومحتوى؛ لا يحمل منطق عمل |
| `MetricCard` | عنوان، قيمة، نطاق زمني، حالة تحميل/خطأ، رابط إلى التفاصيل |
| `StatusChip` | نص + أيقونة + لون للحالة؛ تعريف واحد للحالات في التطبيق |
| `ActionQueueItem` | أولوية وسبب وإجراء واضح وتاريخ؛ لا يدعي درجة خطورة بلا قاعدة |
| `ResponsiveEntityList` | بطاقات في الهاتف، صفوف/جدول مبسط في المساحة الواسعة، مع pagination من الخادم |
| `FilterBar` | بحث مؤجل قصيراً، عوامل قابلة للإزالة، وإعادة تعيين ظاهرة |
| `AdminFormSection` | عنوان، شرح، حقول، أخطاء ميدانية، مؤشر تغييرات غير محفوظة |
| `ConfirmActionSheet` | ماذا سيحدث، من سيتأثر، الإجراء والتراجع إن وجد |
| `AsyncStateView` | هيكل تحميل، فراغ مفيد، خطأ مع إعادة محاولة، وصلاحية مرفوضة |

لا تجعل كل مكون عاماً مبكراً؛ استخرج المشترك حين يظهر استعمالان حقيقيان على الأقل.

## RTL وإمكانية الوصول

- استخدم `EdgeInsetsDirectional` و`AlignmentDirectional` وأيقونات اتجاهية حيث يلزم؛ اختبر رجوع الشاشة وتتابع التركيز مع RTL.
- اجعل المسميات العربية قصيرة ومباشرة. لا تخلط اتجاه رمز المادة أو البريد أو رابط الملف بالنص العربي؛ استخدم `Directionality.ltr` للمعرفات التقنية فقط.
- اجعل جميع الأزرار والبطاقات التفاعلية ذات `Semantics` مفهومة، وادعم TalkBack وVoiceOver ولوحة المفاتيح على الأجهزة الكبيرة.
- اختبر التكبير، الوضع الداكن، تقليل الحركة، التباين، حالات اللون، وتغير حجم النافذة. معيار Flutter العملي يشمل حجم لمس مناسباً وتباين النصوص وعدم انقطاع المحتوى عند تكبير الخط.
