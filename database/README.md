# قاعدة بيانات Hasobjy وخريطة ERD

**إصدار التصميم المحلي: 2026-10-15.** هذا المجلد يجمع SQL المصدر من Notion والتعديلات المحلية والمخططات وقاموس الجداول. لا يوجد اتصال بقاعدة إنتاج أو ترحيل مطبق على خادم خارجي. PostgreSQL هو صيغة التصميم المنقول؛ تقنية الخادم والاستضافة والتفويض النهائي ما زالت D07.

## الملفات وطريقة القراءة

1. [المتطلبات والقصص الـ35](../plans/10-notion-requirements.md) — السلوك ومصدره وخطة تنفيذه.
2. [المصدر الأصلي](source/notion-2026-10-15.sql) — 13 كتلة SQL بالترتيب من صفحة Notion، دون تصحيح؛ 76 جدولاً و630 حقلاً و141 مفتاحاً أجنبياً، تأكد العد في محرك الاختبار.
3. [التعديلات المحلية](amendments.sql) — قيود وجداول وViews وTriggers مضافة وفق توضيحات المنتج والتدقيق.
4. [schema.sql](schema.sql) — مخطط مستقل مولد لقاعدة فارغة، من المصدر والتعديلات؛ ليس migration لقاعدة قائمة. يتضمن 80 جدولاً و155 مفتاحاً أجنبياً و8 Views.
5. [ERD](erd/README.md) — كامل مع الحقول، وكل العلاقات، وتسع وحدات قابلة للقراءة في Markdown/Mermaid.
6. [قاموس الجداول](data-dictionary.md) — تعريف كل جدول وحقوله ومراجعه. قيود ALTER والـTriggers تبقى في SQL المرجعي.
7. [ملخص آلي](schema-summary.json) — قوائم أعمدة الجداول وعدد المفاتيح، تقارن مع كتالوج PostgreSQL أثناء التحقق.
8. [فهرس صفحات Notion وصورها](../docs/notion/README.md) — النسخة الخام وبصماتها وحالات الصفحات وقت التصدير.

## التعديلات على المصدر

- نطاق مستوى الطالب والموضع والباقة 1..2. `academic_years` عام تقويمي، و`study_year` المستوى الأول/الثاني.
- `department_subjects` يميز القسم/المادة/السنة/الفصل، بدلاً من حصر المادة في موضع واحد للقسم. نسخ المنهج بين الدفعات ما زالت قراراً قبل البيانات الحقيقية.
- `free_preview_count` افتراضه 1 وقابل للزيادة. `v_lesson_preview` يحسب أول N دروس **منشورة**؛ حُذف علم `is_free_preview` الحر من الجدول المحلي.
- PDF الأكاديمي DOWNLOADABLE ومجاني. PDF الكورس VIEW_ONLY أو ENCRYPTED_IN_APP وغير مجاني، دون افتراض سياسة للجميع. ملكية PDF عبر الحاوية أو الدرس، واحدة قبل النشر.
- `grading_schemes` يحفظ نسخة نظام المادة للفصل، الأوزان والحدود الخام وحد النجاح 50/60 ومصدر الاعتماد. لا بيانات مواد/أسعار مفترضة. النظام المستخدم لا يعدل؛ تنشأ نسخة جديدة.
- `grades.total_mark` يحسبه Trigger من الدرجات الخام وحدود المكونات، مع 100/0 ودون ضرب الوزن مرتين. مدخل OCR الموزون أصلاً يجب تحويله إلى المقياس الموثق أو اعتماد نظام حدوده تساوي نقاطه الموزونة قبل الحفظ.
- العلامة المنشورة تحتاج اعتماد أدمن؛ صف OCR مطابق ومراجع ودفعة APPLIED، أو كشف قديم APPROVED لطالب مؤهل إدارياً. تعديل العلامة المنشورة يحتاج سبباً ويحفظ `grade_revisions`، ولا تحذف النتيجة المنشورة.
- `product_bundle_subjects` يثبت عضوية الباقة عند الشراء؛ تعديلها أو تغيير ربط/سعر منتج مشتَرى يحتاج إصدار منتج جديد، إلى أن تعتمد سياسة ترحيل D23.
- عملة السعر صريحة دون DEFAULT SYP لأن اختيار الليرة/الدولار/الاثنين لم يعتمد؛ لا توجد أسعار إنتاج مفترضة.
- `protected_pdf_licenses` يربط نسخة PDF والجهاز والاستحقاق والانتهاء، دون مفتاح فك تشفير. تنزيل PDF الكورس يحتاج رخصة مطابقة، وتنزيل الفيديو يحتاج طلب رخصة OFFLINE ممنوحاً مع الأصل والجودة والجهاز الصحيحين.
- رخصة جديدة لا تصدر بعد انتهاء الاستحقاق ولا تتجاوزه، ويجب تطابق مستخدم الجهاز ومستخدم الدفع. هذه قيود بيانات؛ الرخصة الموقعة والوقت الآمن والتشفير ينفذها مزود DRM/المنصة.
- MCQ المنشور له خيار صحيح على الأقل. لا ينقل خيار إلى سؤال آخر، ولا تقدم إجابة من سؤال غير سؤال المحاولة. النموذج الحالي خيار واحد مقدم لكل محاولة؛ تعدد المقبول لا يساوي واجهة اختيار عدة خيارات.
- تفاصيل الدفع توافق الطريقة، والدفعة PAID تحتاج تفصيلاً موثوقاً: API متحقق من المبلغ/العملة، أو إيصال معتمد، أو منح بسبب ومراجع، أو قسيمة لنفس المنتج. API ملزم بمطابقة المستفيد ومرجع العملية ومنع تكرار الإيصال والتسوية قبل المنح؛ تفاصيل المزود لم تعتمد بعد.
- ثوابت ملكية الصفوف وسجلات الرخص والمراجعات محمية من النقل/التعديل المباشر. الوصول العام للجداول والدوال مسحوب من PUBLIC؛ لا عميل يتصل بحساب مالك السكيما.

## Views الموجودة فعلياً

| View | دورها وحدودها |
| --- | --- |
| `v_lesson_preview` | أول N دروس منشورة لكل حاوية |
| `v_pdf_content` | مالك PDF وحالته ومجانيته عبر ربط الحاوية أو الدرس |
| `v_entitlement_scope` | توسعة منتج مادة/كورس/باقة إلى حاويات المحتوى |
| `v_effective_access` | حق نشط مدفوع لمستخدم نشط ومحتوى منشور داخل فترة الخادم؛ لا يشمل استثناء رسوب غير معتمد |
| `v_lesson_completion` | إكمال درس أكاديمي باجتياز التمارين المنشورة، دون حد مشاهدة؛ NULL لدرس بلا تمارين إلى D27 |
| `v_container_progress` | عدد الدروس المكتملة والمنشورة لكل طالب نشط في المحتوى؛ نسبة نهائية لا تعرض حتى معالجة شروط D27 |
| `v_academic_progress_inputs` | نتائج منشورة ومقاييسها لتجميع التقدم العام والمعدل بعد اعتماد قواعد الإعادة/التكميل والساعات |
| `v_weekly_activity_inputs` | جلسات الاستخدام وأوقاتها ومدتها؛ لا تختار بداية أسبوع أو منطقة زمنية أو توزيع جلسة عابرة بالتخمين |

طلبات ERD الخاصة بالمعدل التراكمي والتقدم العام والوقت الأسبوعي محفوظة بالكامل، لكن **Views التجميع النهائية غير منفذة** لغياب سياسة موثقة (D18/D22/D23/D27). أسماء المدخلات لا تعني أن المؤشرات النهائية مكتملة. حساب نسب المشاهدة لا يحل محل إكمال تمارين الدرس.

## نقاط غير محسومة في نموذج البيانات

- SQL المصدر يجعل SUBJECT نفسه حاوية للدروس؛ الخطط القديمة فصلت AcademicCourse عنه، وتعديل Notion لا يحسم عدد دورات/مدرسي المادة. لا يوجد جدول بيانات مدرس أو AcademicCourse متعدد معتمد. D26 مطلوب قبل تنفيذ API ذلك الجزء.
- تحديد نسخة المنهج لكل دفعة، وزن الساعات، اختيار النتيجة المعتمدة عند التكميل/الإعادة، استثناء الرسوب ومدته، والمنطقة الزمنية الرسمية.
- مدة الكورس: `duration_mode` FINITE أو LIFETIME صراحة دون افتراضي؛ ليس ذلك اختياراً لأحدهما من جانب المطور. إنتاج رخصة offline حتى لكورس دائم يحتاج سياسة تجديد معتمدة D09.
- مصدر صور العلامات والهوية الأكاديمية والاحتفاظ، سياسة دفعات OCR الجزئية، واستئناف/اعتراض مراجعة العلامات.
- عدد المدرسين وتاريخ استبدال فيديو منشور دون إفساد الرخص القديمة، وتفاصيل عقود OCR/Gemini/الدفع.

## توليد الملفات والتحقق

```sh
python3 database/build.py
```

هذا أمر محلي بلا شبكة وبلا اتصال بقاعدة بيانات. يعيد SQL وERD والقاموس والملخص الآلي. لا تعدل ملفاً مولداً وحده؛ غير `build.py` للمواءمات الدقيقة أو `amendments.sql` ثم أعد التوليد. تبقى نسخة Notion الأصلية ثابتة.

التحقق المعزول يستخدم PostgreSQL/WASM عبر [PGlite](https://pglite.dev/docs/about) مع امتداد citext؛ أداة اختبار فقط، وليست اختياراً لقاعدة التطبيق. جرى تثبيت الإصدار 0.5.10 في مجلد مؤقت خارج المستودع:

```sh
npm install --prefix /tmp/hasobjy-db-validation-20261015 --no-audit --no-fund @electric-sql/pglite@0.5.10
node database/verify.mjs /tmp/hasobjy-db-validation-20261015/node_modules/@electric-sql/pglite
```

الاختبارات تتحقق من بناء المصدر والمخطط المحلي، تطابق أعمدة/مفاتيح ERD مع كتالوج PostgreSQL، سنوات الدراسة والجهاز والمعاينة والعلامات وOCR وMCQ والدفع والرخص وPDF. النتائج موثقة في [تقرير التحقق](validation-2026-10-15.md). لا تتصل هذه الأداة بأي خادم أو بيانات حقيقية.

قبل إنتاج فعلي يلزم اختبار على PostgreSQL المستضاف المختار، معاملات متعددة الاتصالات والتزامن، سياسات أدوار الخادم وعزل قراءة الطالب، نسخ احتياطية واستعادة، API، وDRM على Android/iOS حقيقيين. السكيما لا تشفر الفيديو أو PDF ولا تمسح جهازاً غير متصل.

تستعمل القيود الفريدة والمفاتيح الخارجية للقيود الممكنة، وTriggers للقواعد بين الصفوف؛ ذلك يوافق حدود [قيود PostgreSQL](https://www.postgresql.org/docs/current/ddl-constraints.html). صلاحيات API لا تستنتج من نجاح قيد قاعدة بيانات.
