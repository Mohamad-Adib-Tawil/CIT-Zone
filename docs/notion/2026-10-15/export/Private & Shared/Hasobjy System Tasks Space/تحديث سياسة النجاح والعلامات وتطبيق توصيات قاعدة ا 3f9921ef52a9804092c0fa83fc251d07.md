# تحديث سياسة النجاح والعلامات وتطبيق توصيات قاعدة البيانات

الحالة: TODO

الهدف
مواءمة خطة العلامات الحالية ومخطط PostgreSQL مع التوضيح الجديد حول حد النجاح، ثم استكمال فجوات قاعدة البيانات الواردة في مراجعة Hasobjy.

معلومة محدثة من صاحب المنتج — 14 أكتوبر 2026
• حد النجاح 50 لبعض المواد و60 لمواد أخرى.
• غالباً حد النجاح 60 للمادة ذات 40% عملي، و50 لبقية المواد. هذه علاقة أولية بسبب كلمة «غالباً»؛ يجب اعتماد حد النجاح ووزن كل مادة من مصفوفة رسمية قبل تجهيز بيانات الإنتاج.
• أوزان التقييم مستقلة: 60 نظري/40 عملي، أو 70/30، أو 100/0 نظري فقط.

التوصيات

1. أضف GradingScheme مرتبطاً بالمادة والفترة/المنهج، يحوي theoretical_weight وpractical_weight وpass_mark ونسخة القاعدة ومصدر اعتمادها. لا تستخدم DEFAULT 60 عاماً.
2. تحقق أن كل وزن بين 0 و100 ومجموعهما 100، واسمح بوزن عملي صفر. احسب الدرجة من الدرجات الخام والحد الأعلى لكل مكوّن؛ لا تطبق الوزن مرتين على بيانات موزونة مسبقاً. خزّن الغياب كحالة مستقلة عن الصفر.
3. أبقِ إدخال العلامات حسب الخطة الحالية: رفع إداري جماعي، OCR كمسودة، مطابقة بمعرف أكاديمي، مراجعة بشرية، واعتماد صريح. التعديل بعد النشر يسجل revision وسبباً.
4. اجعل رفع كشف الطالب القديم قناة انتقالية فقط؛ يتحقق منه الفريق ثم يدخل العلامات ويعتمدها إدارياً. لا تكفي الوثيقة أو اختيار الطالب لمادة إعادة لنشر علامة أو إثبات رسوب.
5. صحح نطاق سنوات الدراسة ليكون 1..2. استكمل تعريف Views وTriggers المذكورة في ERD للتحقق من التقدم، الوقت، المعدل، MCQ، الدفع، وملكية الجهاز/الاستحقاق؛ استخدم FK/قيود الصف أولاً حيث تكفي.
6. ميّز ملفات PDF الأكاديمية المجانية عن PDF الكورسات المحمية. للكورسات: تخزين مشفر داخل التطبيق ومفتاح محمي بالنظام، أو عرض مباشر فقط؛ لا افتراض تنزيل مجاني افتراضي.
7. انتهاء التنزيل يكون برخصة DRM يصدرها الخادم وتنتهي مع الاستحقاق؛ Widevine على Android وFairPlay على iOS بعد إثبات فعلي. يمنع DRM التشغيل بعد الانتهاء، ويحذف التطبيق الكاش عند أول تشغيل/اتصال لاحق؛ لا يمكن مسح جهاز غير متصل فوراً.
8. اجعل عدد دروس المعاينة إعداداً لكل مادة/كورس، افتراضه درس واحد، ويمكن زيادته. يفرض الخادم معاينة أول N دروس منشورة؛ قرروا بشكل مستقل هل تمارين المعاينة مجانية.

معايير الإنجاز
• مصفوفة رسمية لكل مادة تحدد وزن النظري والعملي وحد النجاح 50 أو 60.
• اختبارات حساب لخطط 60/40 و70/30 و100/0، وحدود النجاح والغياب والدرجات غير الصالحة ومصدر علامات موزون مسبقاً.
• صف OCR غير المطابق لا يمكن اعتماده، ولا تؤثر إلا العلامات المعتمدة في التقدم وكشف الطالب.
• مراجعة SQL كاملة تثبت القيود وViews وTriggers، ثم اختبار DRM دون اتصال وانتهاء الرخصة وحذف الملف عند عودة التطبيق.

المرجع الحالي لإدخال العلامات هو plans/features/13-grades-ocr.md، وقرار D18 ما زال مفتوحاً إلى أن تعتمد مصفوفة المواد وسياسة الإعادة.
